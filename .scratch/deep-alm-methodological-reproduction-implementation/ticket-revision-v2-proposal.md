# Deep ALM implementation tickets — Revision 2 proposal

Type: ticket-breakdown-proposal
Status: awaiting-breakdown-approval
Date: 2026-09-07

本文件是待确认的增量拆分草案，不是可领取的实现票，也不替代现有票据。依据是 [Revision 2 规格](../deep-alm-methodological-reproduction/spec.md)。确认后才逐张更新现有实现票并新增独立票据；本次不修改规格、Wayfinder map、源代码或测试。

## 变更边界

- 保留现有编号及完成历史。02–04 保持原样；01 已有运行骨架实现提交，但票面仍为 `ready-for-agent` 且验收框未勾选。发布时先核对原票验收证据，再补记状态和依据，不把 Revision 2 的新要求追记成旧票已经完成。
- 05–10 保留金融建模工作：无互换、60/180 次完整月度转移、29 维行动、所有已确认公式与事件时序均不缩减。
- 11–19、21–23 按本机完整流程调整。新增本机必做票 25–27，分别覆盖运行预算、可替换输入、GPU 移植。
- 20、24 保留编号，转为 `needs-triage` 并标记 `Execution scope: opt-in-research`，作为延期研究范围记录，不进入当前实现 frontier。启动研究时另行确定预算并拆分扩展矩阵、研究报表和正式验收，不能因本机结果不佳自动启动。
- 本机实现票发布为 `ready-for-agent`，标记 `Execution scope: local-delivery`；依赖的真正完成情况仍决定能否领取。新票追加编号，不重排历史 ID；执行按依赖关系而不是文件数字排序。
- 不增加顶层接口，不修改 Paper/Corrected 两种口径的 ADR。较小网络属于容量配置，不是新的金融口径。

## 拟议票据与依赖

以下按建议依赖顺序列出。每项的“交付”是该票完成后可演示或验证的行为，而不是单独的一层实现。

1. **25：预览并限制本机运行**（新增）

   **Blocked by:** 03 / Generate HJM-PCA scenarios（包含已实现的运行骨架与数据前置能力）。

   **交付：** 用户可先查看完整运行计划，再执行受预算约束的真实市场阶段；默认不会启动大规模训练。
   - 增加 `local_flow` 默认配置：Corrected，32/32/32 条训练/选择/测试路径，两轮，batch 8，compact 网络；保留显式选择的旧 quick/paper_scale，并要求 bank_training 显式指定规模、架构、设备和限制。
   - 运行规模、网络宽度、金融口径和验收目的独立解析、校验、版本化及哈希；设备在生成 manifest 前一次解析为 CUDA、MPS 或 CPU，拒绝不支持的组合。
   - 计划列出 8 个主训练任务、64 次主更新、两次 paper-width 检查，以及选择/测试、分析、报告和额外恢复/性能探针的成本。未知训练耗时标为尚未测量，不编造估时。
   - 用实际 HJM 阶段演示计时、批量路径生成及预算耗尽后的非零退出与诊断保留；此时不能声称训练已跑通。
   - 时间默认 1,800 秒，RSS 和可用的 accelerator allocated memory 各自默认 4 GiB 软限制；分开报告、不相加，缺失计数器标为不可用。检查阶段/批次边界与大分配之前，记录在途工作超时，不承诺硬实时截止。
   - CPU 路径身份由 split、epoch、seed、global path index 决定；不同 batch 划分回放一致，5/15 年创新前缀一致。使用注入时钟/内存读数验证守卫，不靠长时间等待或故意耗尽内存。

   - 初始快照验证是独立可执行阶段。通用输入格式和非标准银行的扩展验证归 26，不重复开发第二套银行模型。

4. **26：验证可替换的银行与市场输入**（新增）

   **Blocked by:** 06 / Run a passive runoff simulation。

   **交付：** 用户可导入不同于标准参考案例的合成银行及匹配市场输入，验证、保存、重载并完成被动滚动。
   - 提供有版本的快照导入/导出、schema、示例及映射说明；覆盖估值、六条梯子、成本、增长/利差、产品假设、币种/百万计量单位、估值日、曲线身份与 provenance。
   - 通过既有 ReferenceBankProvider 和 MarketScenarioModel 契约接受匹配输入；非标准合成样本不得被悄悄重建为 10,000 mCHF、2022-07-15 的标准银行。
   - 区分标准案例的组合/久期目标与通用的会计、有限值、形状、符号、单位及日期一致性校验。非标准样本按其声明的目标和假设验证。
   - 拒绝不支持的产品、超出支持期限的现金流、混合币种与市场/快照不一致，不默默截断或转换；不实现 FX 聚合。
   - 用合成数据验证保存/重载身份与滚动现金一致性；实际银行源系统连接、数据抽取和业务映射签字留给银行环境。

9. **11：小规模训练 BM^E 并测量成本**（调整）

   **Blocked by:** 10 / Integrate constraints and the training objective；25 / 预览并限制本机运行。

   **交付：** BM^E 在两种完整期限上真正训练、按选择集挑选并重载 checkpoint，同时产生首次训练资源实测。
   - 保留等期限分配、两个共享规模调整量、RAdam、四轮三角学习率周期、0.2 梯度裁剪和逐轮更新的路径及 mu/lambda。
   - 默认每个期限 2 轮、每轮 4 次更新；每轮末评估 selection 并以总损失/罚项决定 checkpoint，不要求 20 轮 warm-up。最终测试集在 17 中统一使用，本票不提前消费它。
   - 只保留当前训练轨迹批次和至多一个预取情景批次；保留完整时序计算图，更新后释放。评估无梯度，数值失败保留位置诊断。
   - 测量 60/180 月完整 forward/backward/update 的时间与峰值内存，分离 warm-up、情景、评估和写产物时间；设备同步计时。优先复用主训练更新，额外探针单列预算。
   - CPU 和可用 MPS 验证有限值、裁剪与合适夹具上的真实参数更新；设备不可用记录 not-run。完整恢复语义在 21 验证，不在两张票重复实现。

10. **21：受预算约束的训练中断与恢复**（改名并提前）

    **Blocked by:** 11 / 小规模训练 BM^E 并测量成本。

    **交付：** 一次小型真实训练可以在预算耗尽/取消后保存一致进度，重启恢复并与未中断的 CPU 对照一致。
    - 保存最后完成 epoch 的模型、优化器、scheduler、选择历史、数据/配置/seed 身份；重放被中断的 epoch，不丢失或重复已经完成的 epoch。
    - 中断首轮且无完整 checkpoint 时明确从初始登记状态重放，不伪造 checkpoint；后续 MM 的 preprocessing 与冻结 BM^D 依赖使用相同恢复契约。
    - 校验语义兼容性，拒绝更换宽度、数据、口径、期限的续训；设备、输出位置、增加资源预算等允许覆盖须单独记录。
    - 短夹具覆盖完整学习率升降周期、early stopping 配置与恢复；保留 quick/paper_scale 历史参数及 bank_training 显式配置能力，不执行 40,000 路径矩阵。
    - 超预算、OOM、取消和操作失败可区分；保留产物、未完成项及实际资源，非零退出且不给出 development-validated。

    - 验证 stop-gradient 前向不变、阻断当前观测历史的输入梯度、保留策略参数和行动经未来转移到损失的梯度。容量变化不改变金融口径。

19. **27：验证单设备移植与银行交接流程**（新增）

    **Blocked by:** 16 / 训练 15 年 MM 并验证 5 年截断；26 / 验证可替换的银行与市场输入。

    **交付：** checkpoint 可经 CPU 读取并映射至明确设备；提供可在银行执行的小型单 GPU 验证配置与完整交接说明。
    - 同一 PyTorch simulator/policy/trainer 使用设备感知的张量、优化器和恢复路径，支持 CPU/MPS/CUDA 选择，不嵌入 Mac 本机路径或设备专属金融公式。
    - checkpoint 包含架构/参数、优化器/scheduler、epoch、特征 PCA、冻结 BM^D、seed registry、数据/快照/配置/代码身份和 schema 版本；拒绝不兼容预处理/数据及跨宽度续训。
    - 实际执行本机可用设备的加载与短恢复测试；提供同样的 CUDA 集成测试。无 CUDA 时记录 not-run，不以 mock 通过冒充硬件验证，也不承诺跨设备逐位相同。
    - 提供 uv/Linux 安装及运行说明，银行依次检查运行时/设备、合成输入、短 CUDA 训练与恢复、真实数据映射及对账、性能测量，再显式扩大训练规模。
    - compact 权重只作流程证据；银行通常用真实数据重新训练。实际连接/映射签字、多 GPU/DDP、调度、混合精度和集群吞吐优化均须银行侧另行立项及验收，本票不声称已经实现或验证。

21. **23：一条命令跑通并验收 local_flow**（调整）

    **Blocked by:** 22 / 生成精简报告与论文覆盖清单；27 / 验证单设备移植与银行交接流程。

    **交付：** 用户一次调用即可完成真正的 5/15 年端到端流程，并得到基于实测证据的 development-validated 或明确的失败/未完成原因。
    - 串起数据、校准、银行、8 个主训练任务、两次 paper-width 检查、checkpoint 选择/重载、MM(15y|5y)、锁定评估、代表性分析、报告及验收；所有动作受同一次调用预算约束。
    - CLI 的 plan/profile、calibrate、银行构建/导入、train/resume、evaluate/report 和 accept 复用 ReproductionRunner；分阶段产物能重用但须验证语义、代码/数据与 seed 身份，避免重复跑矩阵。
    - 50,000 个 one-step 市场统计检查单列为有界 CPU 验证组，不是完整轨迹训练预算；只在代码/数据/校准/口径/seed/runtime 匹配时复用证据。保留独立数值 oracle，不能靠重复自身公式自证。
