# Deep ALM: local workflow validation and bank training portability

Type: spec
Status: ready-for-agent
Revision: 2 — 2026-09-07

This revision changes execution scope and delivery acceptance following the user's decision to validate the complete technical workflow on a MacBook and perform substantive training later with real bank data on bank GPU infrastructure. It supersedes conflicting run budgets, experiment requirements, and delivery gates in the earlier Wayfinder decisions and implementation tickets. Financial formulas, the no-swap product universe, both horizons, and the locked convention boundary remain applicable.

## Problem Statement

The user wants a maintainable Python and PyTorch implementation of the complete no-swap workflow in *Deep treasury management for banks*. The MacBook is the development and workflow-validation environment. The eventual bank environment supplies real data and GPU resources for substantive training and optimization. Spending substantial local compute to approach the paper's trained results does not serve the user's immediate goal.

The repository already contains the uv environment, audit-run skeleton, SNB ingestion and term-structure reconstruction, HJM-PCA scenario generation and diagnostics, and a Hull-White comparison implementation. These implementations and their useful tests are retained. The Reference Bank, differentiable ALM transitions, policies, training, and integrated evaluation remain to be built. Existing ticket completion records are not a substitute for validating the completed workflow against this revised specification.

The paper's method is implementable, but its collaborating bank's initial cash-flow ladders, absolute scale, product allocations, loan spread, operating costs, trained parameters, and random paths are unavailable. Several numerical details are unstated, and two written formulas have material alternative interpretations. The project must therefore produce a methodological reproduction based on real public market data and an explicitly synthetic Reference Bank, not claim exact numerical recovery of the private experiment.

The previous plan's full networks, repeated policy experiments, sensitivity retraining, and paper-scale economic acceptance requirements are excessive for the local delivery. The implementation must retain inspectable financial assumptions, distinguish Paper and Corrected conventions, cover 5-year and 15-year horizons, and exclude swaps while making local work bounded. Local evidence must establish financial and computational correctness; bank training must establish suitability for the bank's actual use case.

## Solution

Build one package-first pipeline whose single external seam accepts a resolved run configuration and produces a traceable run bundle. Small local runs and larger bank runs use the same financial simulator, policy implementations, optimization logic, and artifact contracts. The pipeline will:

1. ingest and validate the SNB NSS parameter export;
2. reconstruct historical continuously compounded spot, discount, and monthly forward curves;
3. calibrate three-factor HJM-PCA volatility functions and generate reproducible 5-year and 15-year market scenarios;
4. construct a transparent, internally consistent Reference Bank from versioned product templates;
5. roll the bank forward through a PyTorch-differentiable monthly ALM simulator;
6. perform a bounded, genuine training pass for BM^E, BM^C, BM^D, and MM at both horizons;
7. exercise checkpoint selection, reload, recovery, locked evaluation, horizon truncation, and representative analysis;
8. generate a compact local report and support explicitly requested extended research reports;
9. validate financial identities, gradients, numerical behavior, reproducibility, resource controls, and artifact completeness; and
10. provide versioned bank-input contracts, portable PyTorch checkpoints, configurable CUDA execution, and an explicit bank-side validation checklist.

The default deliverable is `development-validated`: a complete small Corrected run with financial and engineering evidence. It does not certify convergence, economic superiority, or production suitability. Larger `quick`, `paper_scale`, and bank-configured experiments are opt-in. Historical paper-comparison gates remain documented as a deferred research protocol, separate from local delivery and from future bank acceptance.

## Implementation Decisions

### Architecture and seams

- The reproduction has one external seam: `ReproductionRunner`. Its interface accepts a fully resolved run configuration and returns a `RunBundle` describing status, artifacts, metrics, checkpoints, and acceptance evidence. The CLI is an adapter over this interface and contains no financial logic.
- `MarketScenarioModel` is an internal seam with HJM-PCA and Hull-White extended Vasicek adapters. HJM-PCA supplies training and evaluation scenarios; Hull-White supplies only the Figure 4 diagnostic.
- `ReferenceBankProvider` is an internal seam returning an immutable `ReferenceBankSnapshot`. Local delivery includes the synthetic seasoned-book generator, versioned saved-snapshot import/export, schema documentation, and a synthetic noncanonical import fixture. Mapping actual bank source systems remains bank-side work.
- `TreasuryPolicy` is an internal seam whose interface maps a batch of `PolicyObservation` values to a batch of `TreasuryAction` values. BM^E, BM^C, BM^D, and MM are adapters at this seam.
- `ALMSimulator.rollout` is the primary economic and differentiability seam. It accepts a Reference Bank snapshot, a batch of market paths, a policy, objective parameters, and a resolved convention, and returns a `TrajectoryBatch` without writing files.
- `AcceptanceEvaluator` consumes completed experiment results and returns an immutable `AcceptanceReport`. Artifact rendering and serialization consume returned values rather than reaching into model internals.
- Formula-level helpers remain implementation details inside these deep modules. Tests use constructed inputs and observable results through the highest applicable seam.
- These are the previously agreed test seams; this revision introduces no new top-level testing boundary. Resource controls, stage orchestration, checkpoint recovery, and portable execution are observed through `ReproductionRunner`; financial and policy behavior retain the existing internal seams.

### Core data contracts and tensor layout

- All public data contracts are typed, immutable where practical, and validate units, shape, dtype, device, horizon, and provenance at construction.
- `ReferenceBankSnapshot` contains the as-of date, initial curve identity, cash, equity, target economic values, six nominal cash-flow ladders for mortgages, enterprise loans, investments, funding bonds, non-maturity deposits, and term deposits, operating costs, product assumptions, units, provenance, and a content hash.
- Each snapshot cash-flow ladder has exactly 180 monthly entries. The snapshot itself has no path dimension.
- `MarketScenarioBatch` exposes ALM spot yields, discounts, and forwards with batch-first shape `[paths, H+1, 180]`, plus Brownian innovations, convention identity, seed identity, and calibration identity. Extended HJM tenors are internal to scenario generation and are not exposed as bank state.
- `PolicyObservation` has shape `[paths, 145]`. `TreasuryAction` contains investments with shape `[paths, 13]` and financing with shape `[paths, 16]`; its concatenated representation is `[paths, 29]` and must be non-negative.
- `TrajectoryBatch` contains observable states at `[paths, H+1, ...]`, actions at `[paths, H, 29]`, six constraint values and violations at each applicable decision state, annual masks and dividends, loss components, and reconciliation diagnostics.
- Rates and volatilities are decimal annual quantities, maturities and time steps are in years, and monetary quantities are in mCHF for the canonical Reference Bank. A future single-currency bank snapshot must declare its currency and use millions of that currency consistently; mixed-currency aggregation requires a separate design. Percentage, basis-point, and monetary-unit conversions occur only at input/configuration and reporting edges.

### Configuration and profile resolution

- Resolved configuration includes source data, convention, run scale, architecture, Reference Bank, horizon/experiment, policy, optimization, seeds, resources, output, and acceptance. Architecture, sample counts, epoch/update limits, reporting scope, and resource budgets are configuration values rather than financial-code branches.
- Unknown keys, incompatible combinations, invalid weights, inconsistent horizons, and unit-bearing values without an expected unit fail configuration resolution.
- `paper` and `corrected` are locked convention profiles. Only PCA loading scale and loan-interest annualization differ. Any per-choice override marks the resolved convention `custom`.
- Add `local_flow` as the default run-scale profile. Retain the existing `quick` and `paper_scale` settings as explicitly selected larger profiles; do not silently reinterpret old configurations. Add a `bank_training` profile with explicitly supplied sample sizes, epoch/update limits, architecture, and device, without launching it during local delivery.
- Run scale, model width, market convention, and acceptance purpose are independent axes. Selecting a smaller network or fewer scenarios does not change financial formulas or mark the convention custom. Record the resolved values of every axis and a configuration schema version.
- The fully resolved configuration is serialized and hashed before work begins. The hash participates in run identity and checkpoint compatibility.
- An ordinary end-to-end command defaults to Corrected plus `local_flow`, compact architecture, and `development-validated` acceptance. No generic run command, test command, or resume operation automatically selects `paper_scale` or bank training.
- Architecture presets are `compact` with residual-block widths 64, 64, 32, 32 and `paper` with widths 512, 512, 256, 128. Both preserve four independent 32-feature portfolio encoders, a 145-feature observation, a final 64-feature encoding, the same block topology, and the 29-action contract. Projection layers handle width changes within the shared implementation. Positive custom widths may be supplied and are recorded as architecture choices.
- Local training uses float32 on MPS or CPU; CPU float64 is the reference for numerical and gradient oracles. Add explicit CUDA device selection and availability validation. `auto` resolves once before the manifest is hashed, preferring available CUDA, then MPS, then CPU. Unsupported device/dtype combinations fail explicitly; device changes during a run are not silent fallbacks.

### Local compute budget and execution plan

- The initial `local_flow` defaults are project engineering choices: 32 fresh training scenarios per epoch, 32 selection scenarios, 32 locked test scenarios, two epochs, batch size eight, one training seed per policy/horizon, and compact MM width. These values are configurable; they are not claimed to be statistically adequate training or measured optimal MacBook settings.
- The mandatory training matrix is four policies at each of 5 and 15 years: eight training jobs, eight optimizer updates per job under the defaults, and 64 main training updates in total. MM(15y|5y) is checkpoint reuse and adds no training job. Benchmarks and MM always use full 60/180-transition rollouts.
- A separate architecture check performs one complete forward, backward, and optimizer update with paper-width MM for each horizon on two paths and the corresponding frozen local BM^D baseline. It shares the implementation but neither replaces the compact checkpoints nor claims paper-width convergence. Its two updates and recovery-test work are listed separately in the execution plan.
- Generate an execution plan before training that enumerates jobs, dependency order, seeds, horizons, widths, sample counts, maximum optimizer updates, evaluations, artifact work, optional stages, and estimated memory. No multi-seed repetition, sensitivity-triggered retraining, or paired Paper training is included implicitly.
- The default total wall-clock budget is 1,800 seconds for one local workflow invocation, including profiling and optional work selected in that invocation. This is a configurable cooperative stop budget, not a promised completion time. Check elapsed time between batches/stages and before expensive allocations; an in-flight optimizer update or artifact write may finish after the limit. Report actual overshoot rather than claiming a hard real-time deadline.
- Default memory guards are a 4 GiB process-RSS soft limit and, where measurable, a separate 4 GiB accelerator-allocated-memory soft limit. They are configurable engineering defaults, measured and reported separately without summing overlapping unified-memory counters. Unsupported counters are labeled unavailable. Pre-allocation estimates and bounded batch generation supplement these guards; an allocation failure remains a typed operational failure.
- Only the current training trajectory batch and at most one prefetched scenario batch are resident for accelerator training. Generate scenarios in batches, retain the complete current batch's temporal gradient graph, release it after the update, and evaluate without gradients. Never materialize all training paths/epochs on the accelerator or retain every batch's computation graph.
- No resource-saving mode may shorten required financial horizons, truncate backpropagation through action-dependent transitions, drop annual events, alter stop-gradient, or clip financial states. If a run cannot complete within its budget, record what remains and rerun only under an explicitly resolved revised budget/profile.
- At the first working training slice, benchmark bounded complete forward/backward/update cycles at 60 and 180 months, including the paper-width checks once the MM dependency is available. Record warm-up separately, use synchronized device timings, and report scenario-generation, update, evaluation, and artifact time plus measured peak memory. Estimates extrapolated from these measurements are labeled estimates; they do not guarantee whole-run time.
- On budget exhaustion or cancellation, preserve the last consistent epoch checkpoint and completed artifacts, record a distinct incomplete/budget-exhausted reason, and return nonzero without `development-validated`. Resume starts at the recorded epoch boundary with the same seeds and replays an interrupted epoch. Raising only a runtime budget is a permitted, audited resume change; changing data, convention, width, or horizon is not.

### Bank integration and GPU portability boundary

- Local delivery provides a versioned saved-snapshot schema, import/export and validation behavior, representative synthetic input examples, and a mapping guide for valuations, six cash-flow ladders, product assumptions, costs, growth/spreads, units, as-of date, curve identity, and provenance. A synthetic noncanonical snapshot verifies that the loader does not silently rebuild the canonical 10,000 mCHF bank.
- Reference Bank targets, its 2022-07-15 initial curve, CHF calibration window, and synthetic duration targets are reference-case requirements. A future bank adapter supplies its own compatible valuation date, historical market inputs or scenario batches, balances, currency, and approved assumptions. Generic validation still enforces accounting, shape, finite values, nonnegative contractual ladders, units, and curve/snapshot consistency. Inputs with unsupported products, currencies, or maturities are rejected rather than silently truncated or forced into canonical proportions.
- Real-bank market data and bank snapshots enter through `MarketScenarioModel` and `ReferenceBankProvider`. The local deliverable documents these contracts and tests them with synthetic inputs; actual data extraction, source-system connections, and mapping sign-off require the bank environment. Loading a differently calibrated market or bank snapshot must not silently reuse an incompatible feature transform or trained checkpoint.
- Keep tensor creation, batch transfer, dtype selection, optimizer construction, and checkpoint restore device-aware. The same PyTorch model and simulator must support macOS CPU/MPS and Linux CPU/CUDA without embedded local paths or device-specific financial formulas. Provide uv-managed installation and execution instructions and a small bank-side commissioning configuration; dependency and CUDA runtime compatibility must be checked on the target machine.
- Checkpoints can be loaded through CPU and mapped to an explicitly requested supported device. They contain model architecture, weights, optimizer/scheduler state, completed epoch, feature-PCA identity, frozen BM^D dependency, seed-stream identity, data/snapshot/configuration hashes, and schema versions. Changing hidden widths requires a new training run; local compact weights are not automatically transplanted into a full-width bank model.
- Bank training scale is configured independently of the historical paper scale. A bank model normally trains anew on bank data; its own approved objectives, portfolio assumptions, and validation standards determine economic acceptance. Changing paper financial logic is a separate explicit modeling change, not an automatic consequence of switching devices or data sources.
- CPU scenario generation streams deterministic path identities defined by split, epoch, seed, and global path index, so replay and batching do not change the intended scenarios. Persist selection/test identities and process their larger tensors in bounded chunks. Do not rely on worker scheduling or accelerator count as the only random identity.
- Implement the portable single-device CUDA execution path, but only claim CUDA validation after running the bank-side checks on a CUDA machine. MacBook delivery marks CUDA runtime checks not run when unavailable. Multi-GPU distributed training, inter-node communication, cluster scheduling, mixed precision tuning, and target-environment throughput optimization are deferred bank-side work with separate tickets and acceptance; local portability is not a claim that cluster training has been implemented or verified.
- The bank commissioning guide must cover dependency/device inspection, synthetic input validation, a short CUDA training-and-restore run, real-data mapping/reconciliation, a resource benchmark, and only then a configured larger training run. Bank-side evidence records hardware/runtime versions, mapped-data identity, financial and gradient results, resume results, and measured throughput before scaling beyond one GPU.

### SNB ingestion and curve reconstruction

- The SNB loader accepts the long-form `rendopar` export with UTF-8 BOM, semicolon delimiter, metadata/header lines, and parameter codes `b0`, `b1`, `b2`, `b3`, `t1`, and `t2`.
- Parameter rows are pivoted by date only after duplicate-key, date, numeric, and all-six-parameters completeness checks. Fully blank parameter dates are excluded; partial dates are an error.
- HJM calibration uses complete observations from the inclusive paper window 1 January 2005 through 15 July 2022. Data after the end date is ignored for calibration. Earlier data needed for the initial deposit reference-rate history remains available.
- NSS spot curves are reconstructed with stable small-tenor evaluation. Beta values are converted from percentage points to decimals exactly once; tau values and tenors remain in years.
- Monthly tenors are 1/12 through 180/12 years. Discount factors use continuous compounding. Discrete monthly forwards are derived from adjacent log discount factors and must round-trip to spot rates and discounts.
- Analytic NSS instantaneous forwards are produced only as a diagnostic and do not alter the convention profile.

### Weekly PCA calibration and cubic volatility functions

- Daily reconstructed forward curves are grouped on a Friday-ending weekly calendar and represented by the last valid observation in each week. No parameter interpolation, curve interpolation, outlier deletion, Friday-only filtering, or every-fifth-observation shortcut is used.
- Consecutive weekly forward curves are differenced arithmetically. Their centered sample covariance uses divisor `n-1` and is multiplied by 52 before eigendecomposition.
- Eigenpairs are ordered by descending eigenvalue. Each eigenvector sign is stabilized by requiring its largest-absolute-value element to be positive.
- Three components are retained. Paper loadings are eigenvalue times eigenvector; Corrected loadings are square-root eigenvalue times eigenvector.
- Each scaled loading is fitted by ordinary unweighted cubic least squares with an intercept on normalized tenor `u=x/15`. No zero-tenor constraint, tenor weighting, or clipping is applied.
- Calibration artifacts include selected dates, historical curve matrices, differences, covariance, eigenpairs, explained variance, signed and scaled loadings, cubic coefficients, PCA truncation error, polynomial fit error, and each convention's implied covariance.
- The user's accepted cubic-fit deviation is recorded explicitly: original individual 15% and aggregate 10% fit limits are diagnostic reference levels, not blocking gates. Report observed errors and their impact on implied covariance without changing the fitted polynomial, PCA scaling, or calibration sample. Three-component explained variance of at least 90% and numerical consistency checks remain required for the reference calibration.

### HJM-PCA and Hull-White scenarios

- HJM coefficients are time-homogeneous tenor functions. The drift uses the HJM restriction with the decided volatility loading for the active convention.
- The volatility integral starts from the fitted polynomial value at tenor zero and uses the trapezoidal rule on the monthly grid. The cubic analytic integral is a validation oracle only.
- The Musiela tenor derivative uses the paper's forward difference. Euler-Maruyama uses `dt=1/12`, independent standard-normal factors, and an explicit square-root-time multiplier.
- The initial extended grid contains `N+H` monthly nodes: 240 for a 5-year run and 360 for a 15-year run. NSS and cubic functions are evaluated through 20 or 30 years. Each step updates the first `L-1` nodes and discards the old final node; ALM receives the first 180 nodes.
- A 5-year market batch uses the first 60 innovations of its paired 15-year seed stream. Shared initial nodes and factors must therefore reproduce the same first-60-month market path.
- Finite rates are never clipped. Non-finite forwards, discounts, yields, drift, or volatility terminate the affected run with a typed numerical error and diagnostic context.
- The Hull-White extended Vasicek adapter implements only the paper's scenario-diversity comparator and exposes the same observable curve-batch contract. It is excluded from policy training, selection, acceptance ordering, and Reference Bank sensitivities.
- Training scenarios are generated deterministically by epoch and global path identity without materializing the entire training tensor on MPS or CUDA. Selection and locked test paths are stable CPU artifacts shared across policies, with bounded loading for larger bank runs.

### Reference Bank construction

- The canonical Reference Bank has 10,000 mCHF total assets. Economic-value targets are cash 20%, investments 5%, mortgages 55%, and enterprise loans 20%; liabilities are non-maturity deposits 10%, term deposits 40%, and funding bonds 40%. Equity is the residual and must equal 10% within construction tolerance.
- Cash is fixed at its target during initial construction and never used as a silent balancing plug. Each non-cash seasoned ladder is scaled to its target present value using the 15 July 2022 curve.
- Initial portfolios are constructed from stationary historical monthly cohorts using the same contractual templates available during simulation, retaining only cash flows outstanding at the as-of date.
- Mortgage originations span 2 through 12 years. Ten-year mortgages receive 40% and every other eligible original term receives 6%. Enterprise-loan originations split equally across 1, 2, and 3 months.
- Each month's product-level matured principal is replaced. The additional total-loan growth amount equals the current pre-roll nominal loan balance times 3% per year divided by 12, not the initial present value times that rate, and is allocated to mortgages and enterprise loans in the 55:20 initial balance ratio.
- Deposit reference terms are 1 month, 2 months, 1 year, and 10 years. Non-maturity weights are 40%, 30%, 25%, and 5%; term-deposit weights are 10%, 10%, 50%, and 30%.
- Initial investment-bond cohorts use equal issuance across original terms 3 through 15 years. Initial funding-bond cohorts use equal issuance across 3 months and 1 through 15 years. Synthetic legacy pricing uses the initial curve and is labeled as a project assumption.
- The canonical loan customer spread is 150 basis points. Initial personnel cost is 3 mCHF per month and grows 2% at each annual close. Material cost is 1 mCHF per month and remains constant.
- Named one-factor sensitivity variants are: total assets 5,000/10,000/20,000 mCHF; ten-year mortgage weight 20%/40%/60% with residual weight spread equally; ten-year reference-term weight 0%/5%/15% for non-maturity deposits and 15%/30%/45% for term deposits with the offset in the one-year bucket; loan spread 100/150/200 basis points; and operating costs at 75%/100%/125% of canonical values.
- Snapshot construction records disclosed, derived, private-replacement, and unresolved-project assumptions separately. It fails rather than repairing any target-value, accounting, sign, ladder-length, duration, unit, or provenance violation.

### Financial transition rules

- Investments have 13 annual original maturities from 3 through 15 years. Funding bonds have 16 original maturities: 3 months and 1 through 15 years. Bonds are issued at par, pay semiannual coupons, may be fractional, remain non-negative, cannot be sold, and are held to maturity.
- Unit bond cash flows and coupons are derived from the prevailing curve using the paper's pricing rule. Annualized transaction spreads are -15 basis points for investments and +15 basis points for funding.
- Mortgages are default-free. Enterprise loans are impaired at an annual close when the six-month rate increased by more than 2 percentage points over the year. The impairment factor is the excess increase over 2 percentage points, allocated proportionally across outstanding enterprise-loan cash flows; impaired principal stops producing interest.
- Loan contracts are represented by fixed-rate cohorts: every cohort stores its remaining principal schedule and its locked monthly coupon. The aggregate loan cash-flow ladder is reconstructed from principal plus fixed coupons; interest is therefore settled once through that ladder, not also added as a separately repriced cash flow. Legacy synthetic cohorts are constructed from the initial curve plus 150bp customer spread and rescaled to preserve the disclosed initial economic-value targets. New cohorts use the current six-month yield plus spread at issuance, then retain that rate. Paper uses the positive part of the annual effective expression without division by 12; Corrected divides the continuous annual rate by 12 before exponentiation. The shared six-month new-loan rate remains a disclosed simplification relative to a maturity-specific origination curve.
- Deposits grow independently of treasury actions: non-maturity deposits at 4% per year and term deposits at 1% per year, applied monthly. Maturities and reinvested interest are rolled in equal monthly tranches up to their assigned reference term.
- The deposit reference rate is the three-month moving average of the six-month yield. Non-maturity and term-deposit rates use the paper's pass-through, cap, and floor formulas. Monthly interest uses the exponential monthly conversion and is reinvested through the same maturity mechanism.
- Decision-independent monthly cash flow combines matured loans, new loan outflow, loan interest, new deposits, matured deposits, and operating costs.
- Cash earns no positive interest. When the one-month rate is negative, cash above 30 times minimum reserves incurs the paper's negative-rate penalty.
- E-03 correction shared by both conventions: the cash penalty is a non-negative cost and is subtracted from cash. Deposit maturity settlement is offset by a same-month cash inflow for principal renewed; reinvested interest increases deposit liabilities without a net cash payment. In a zero-rate, zero-growth, action-free case, rollover cannot change equity except for operating costs.
- Roll-forward settles the first cash-flow bucket, applies decision-independent cash flow and cash penalties, shifts every 180-month ladder left, appends zero, and revalues outstanding positions at the new curve.
- Restructuring adds action-quantity-weighted unit cash flows to investment and funding ladders. Cash subtracts the sum of investment quantity times value and adds the sum of funding quantity times value. This complete update applies in both conventions.
- At time zero there is no settlement roll or annual close; the first policy decision and restructuring occur. For later decision dates, roll-forward precedes policy and restructuring. Constraints are evaluated after restructuring. Annual closes occur at months 12, 24, and subsequent multiples through `H-12`, after constraint evaluation.
- Annual dividends equal 50% of positive annual profit and reduce cash and equity. The final action occurs at `H-1`; the simulator then performs one roll to state `H` without another policy, restructuring, constraint evaluation, annual dividend, or action.

### Balance sheet, constraints, and losses

- Assets equal cash plus economic values of loans and investments. Liabilities equal economic values of deposits and funding. Equity is always the residual.
- Risk-weighted assets equal 10% of investments plus 35% of mortgages plus 100% of enterprise loans. Equity/RWA must be at least 17%.
- HQLA equals 71% of cash plus 89% of investments. Thirty-day net outflow equals 17.6% of non-maturity deposits plus 13% of term deposits plus 1% of funding. LCR must be at least 105%.
- Available stable funding equals 95% of non-maturity deposits, 90% of term deposits, 60% of funding, and 100% of equity. Required stable funding equals 12% of investments plus 71% of loans. NSFR must be at least 105%.
- Minimum reserves follow the paper's sign-dependent treatment of deposits and equal 2.5% of the eligible base. CMR is cash divided by minimum reserves and must be at least 100%.
- IRS revalues the economic balance sheet under parallel plus and minus 100-basis-point curve shifts and uses the worst absolute equity sensitivity relative to current equity. It must not exceed 8.5%.
- EYR is evaluated only at annual constraint dates and equals annual pre-dividend equity change less 6 mCHF, divided by prior-year equity. It must be non-negative.
- Constraint values used in the next policy observation are the most recently computed post-restructuring values. At time zero, the observation uses constraint values computed on the initial pre-decision snapshot.
- Constraint breach transforms, per-constraint coefficients, time accumulation, and the outer squared penalty follow the paper. Coefficients in LCR, NSFR, CMR, Equity/RWA, IRS, EYR order are 1.0, 0.2, 1.0, 2.5, 2.0, and 0.002.
- Training uses only the asymmetric downside target loss plus `lambda` times the constraint penalty. For each training path and epoch, `mu` is sampled uniformly from 2% to 7% and `lambda` uniformly from 0.05 to 25; both are policy features.
- Evaluation fixes `lambda=3.5`, `mu=4.06%` for 5-year policies, and `mu=4.00%` for 15-year policies. CRRA with `gamma=10` is an evaluation metric only. Its equity-ratio floor defaults to `1e-8`, remains configurable as a numerical safeguard, and is recorded in the manifest.

### Policies and feature construction

- All policies produce separate investment and financing actions through the TreasuryPolicy seam and use the same simulator, objective, scenarios, and optimizer family.
- BM^E uses equal maturity distributions and two learned, time-shared scale adjustments. BM^C learns time-shared investment and financing allocations and scales. BM^D learns independent allocations and scales for every actual decision date in the resolved 60/180-transition timeline.
- Benchmark scale equals the amount maturing in the next period plus a learned adjustment. Final actions are non-negative. The implementation reports actual parameter counts and records the paper's indexing mismatch rather than silently changing the resolved timeline.
- The current yield curve is centered and projected to three dimensions by a second PCA fitted only on training scenario states. The fit uses every state when no more than 50,000 are available; otherwise it takes a deterministic, uniformly stratified sample across path and time indices. Curves are centered but not standardized tenor by tenor. Selection and locked test states are never used. The selected indices and fitted transform are persisted as run artifacts.
- Investment, funding, aggregate loan, and aggregate deposit 180-month ladders are divided by 100 and passed through four independent fully connected encoders, each producing 32 features.
- The 145-dimensional policy observation concatenates 128 portfolio-encoding features, 3 yield-curve PCA features, 5 relative balance-sheet features, 6 previous-constraint features, normalized time `t/T`, sampled or fixed `mu`, and sampled or fixed `lambda`.
- Relative balance-sheet features are total assets relative to initial assets, equity relative to assets, cash relative to assets, investments relative to assets, and funding relative to assets.
- MM uses ELU activations and residual fully connected blocks with configuration-selected compact or paper widths, and a 64-dimensional final encoding before its action heads. Both presets use the same topology and implementation; the compact preset changes capacity, which reports must disclose. Batch normalization is not used.
- MM weights are shared across time. The same network receives `t/T`; for MM(15y|5y), time remains normalized by 15 years when evaluation stops after 60 months.
- The MM action heads produce one scalar deviation and one softmax maturity distribution for investments and for funding. Each deviation is added to the pretrained BM^D action and the final action is passed through ReLU.
- Stop-gradient is applied to the complete 145-dimensional observation immediately before policy evaluation. It is identity in the forward pass, blocks gradients into the state/feature history through the current policy input, and preserves gradients to current policy parameters and through action-dependent future transitions.

### Training, model selection, and reproducibility

- RAdam is used for every learned policy with PyTorch defaults for betas and epsilon and zero weight decay. The learning rate follows a per-update triangular cycle from 5e-4 to 5e-3 and back over four epochs, with two epochs per half-cycle and momentum cycling disabled. Global gradient clipping is 0.2. These undisclosed optimizer and cycle details, along with initialization and other numerical settings, live in resolved run configuration and are labeled as project choices rather than paper facts.
- `local_flow` uses the bounded defaults above. Selection is evaluated after each completed epoch; choose the lowest fixed-parameter selection total loss, with lower penalty loss as the tie-break. Do not require 20 warm-up epochs or statistical early stopping for a two-epoch workflow run. The original learning-rate cycle is retained even though a two-epoch run covers only its first half; scheduler values, save/restore, and the descending half are checked separately with bounded fixtures.
- Legacy `quick` retains 256 training paths per epoch, 128 selection paths, 128 locked test paths, five epochs, batch size 32, paper widths, and complete horizons. It is opt-in and does not start sensitivity retraining or a wider experiment matrix implicitly.
- Optional `paper_scale` retains 40,000 deterministically resimulated training paths per epoch, 1,600 selection paths, 1,600 locked test paths, at most 100 epochs, batch size 32, and paper widths. These defaults are preserved for comparison, not executed as a MacBook delivery requirement.
- Optional paper-scale checkpoint selection begins after epoch 20 and early stopping follows 15 epochs without at least 0.1% relative improvement in selection total loss. The chosen checkpoint minimizes fixed-parameter selection total loss; effectively tied checkpoints prefer lower penalty loss. Bank training uses explicitly configured limits and early-stopping settings; synthetic short runs test these control paths without running the full research budget.
- BM^D is trained before MM at each horizon and convention required by the experiment matrix. MM receives an immutable reference to the selected BM^D baseline parameters.
- Local benchmarks and MM each use one registered training seed per horizon. Three-seed Corrected MM experiments and the paired Paper training matrix are optional research workloads. All selected seeds share the appropriate selection and locked test paths; seeds are never dropped because of poor results.
- Scenario seeds, parameter-sampling seeds, model initialization seeds, data-loader order, bootstrap seeds, and sensitivity seeds are named independently in a seed registry.
- CPU scenario generation is bitwise reproducible for an unchanged environment, configuration, and scenario identity. CPU reference fixtures validate exact replay; MPS/CUDA training records determinism settings and numerical evidence without claiming cross-device bitwise checkpoint equality.
- Checkpoints include resolved configuration identity, convention, run scale, architecture, policy, horizon, seed, epoch, optimizer/scheduler state, preprocessing identity, selection history, baseline dependency, and code/data hashes. Semantic compatibility is validated on resume; permitted runtime-only overrides such as output location, available device, or a raised resource budget are recorded against the parent checkpoint.
- Interruption and resume at completed epoch boundaries are required and tested locally. Replaying an interrupted epoch is explicit; completed epochs are not silently reused or skipped. Local small-network checkpoints are workflow evidence, not recommended pretrained weights for the bank.

## Testing Decisions

- Tests assert external behavior through the highest applicable seam. They do not assert private helper calls, internal class layout, optimizer call order, or plotting implementation.
- Prior art includes the existing run-skeleton, ingestion, market-scenario and comparator tests, the source paper, retained Wayfinder financial decisions, research reports, hand-calculated fixtures, and independent analytic formulas. Preserve useful tests and strengthen them where needed; a round-trip or statistical check must use an independent reconstruction/oracle rather than repeat the implementation's forward calculation.
- Unit tests cover SNB parsing, NSS curve values, continuous discounting, discrete forward round-trips, bond cash-flow pricing, cash-flow shifts, deposit rates and reinvestment, loan growth and impairment, operating costs, dividends, all six constraints, penalties, losses, metrics, signed VaR/ES, and configuration resolution.
- Market-model tests cross the MarketScenarioModel seam. CPU float64 spot/discount/forward round-trip error, PCA orthogonality, retained-covariance identities, initial-curve equality, and deterministic HJM one-step equality must not exceed `1e-10` in the applicable absolute or relative Frobenius measure.
- Reference PCA acceptance retains three-component explained variance of at least 90%. Test that aggregate and component cubic-fit errors are calculated and persisted, including values above the former 10%/15% reference levels. Such values produce visible diagnostics, not blocking failures, as accepted by the user.
- HJM statistical tests retain 50,000 fixed-seed one-step shocks for each convention: factor means within three standard errors of zero and empirical curve-shock covariance within 5% relative Frobenius error of the fitted `V V^T dt` target. They run as a bounded CPU numerical-validation group, not as 50,000 full training trajectories or once per optimizer update. Evidence can be reused only for matching code, source, convention/calibration, seed and runtime identities; invalidation triggers a fresh bounded check.
- ReferenceBankProvider tests cover canonical construction, saved-snapshot round-trip and a synthetic noncanonical import. Canonical portfolio present values match targets within `1e-8` relative error, loan duration is below 5 years and deposit duration below 3 years. All snapshots require 180-entry ladders, nominal cash flows at least `-1e-8`, complete units/provenance and accounting consistency. Noncanonical inputs use declared targets and validation assumptions rather than being rejected for differing from canonical size or allocations.
- ALMSimulator property and integration tests use short deterministic fixtures and full 60/180-step generated fixtures. At every path and state, absolute assets-minus-liabilities-minus-equity and cash-reconciliation error must not exceed the larger of `1e-6` mCHF and `1e-10` times total assets.
- Constraint tests include values just below, at, and just above every bound, plus shifted-curve IRS and annual-only EYR fixtures. Formula error must not exceed `1e-10`.
- Gradient tests run smooth, interior CPU float64 fixtures through ALMSimulator.rollout. Representative autograd gradients must satisfy `|g_auto-g_fd| <= 1e-6 + 1e-4 |g_fd|` against central finite differences. Policy gradient norm must exceed `1e-8` in a fixture whose terminal loss depends on action.
- Stop-gradient tests verify identical forward values with and without detachment, zero or absent gradient into the observation state through the current policy call, finite nonzero gradient into policy parameters, and gradient propagation from current actions through later active and passive transitions to terminal loss.
- CPU/MPS integration tests execute complete float32 optimizer steps for 60 and 180 months with the shared implementation. The paper-width checks use two paths per horizon; states, loss, gradients and updated parameters are finite, clipping is at most `0.2 + 1e-6`, and a suitable fixture proves a nonzero parameter update. CPU float64 oracles retain the original tolerances. CUDA runs the same synthetic integration checks on the target environment; absent hardware is explicitly skipped, not passed.
- Convention tests prove that locked Paper and Corrected profiles differ only in PCA scaling and loan-interest annualization. A per-convention override resolves to custom; selecting another width or resource profile does not. Reject incompatible data/horizon identities for paired comparisons and incompatible architectures for checkpoint restore.
- Policy contract tests exercise BM^E, BM^C, BM^D, and MM through the same TreasuryPolicy interface and assert nonnegative `[paths,29]` output, correct scenario/time dependence, correct maturity availability, and BM^D baseline use by MM.
- Local end-to-end tests run the `local_flow` matrix with actual training, frozen BM^D dependency, training-only feature PCA, checkpoint selection/reload, full 60/180-month rollouts, MM(15y|5y), representative analyses and report generation. A separate short recovery test checks uninterrupted versus resumed CPU execution and scheduler/seed continuity. The optional legacy quick profile uses the same execution engine.
- Configuration/runner tests verify the resolved update count, no automatic paper-scale escalation, independent architecture/convention selection, bounded scenario batches, budget-exhausted status with preserved evidence, and inability to report local success when any required job is omitted. Resource-control fixtures use small deterministic work and an injectable clock/resource reader; they do not need long sleeps or intentional memory exhaustion.
- Portability tests replay identical CPU scenario identities across different batch partitions, load checkpoints through CPU, reject incompatible widths/data/preprocessing, and validate device requests. Target CUDA, real-bank mapping and multi-GPU evidence are tracked separately. A local result cannot mark those deployment checks completed.
- Full research-matrix execution, multi-seed significance, 10,000-resample bootstrap and economic-direction gates are opt-in later acceptance work. Their algorithms may be exercised with bounded synthetic fixtures, but neither running the paper-scale suite nor observing the paper's economic outcomes is required for local delivery.
- Artifact tests validate schemas and semantic content rather than image pixels. Every table and figure must identify its policy, horizon, convention, sample size, metric units, and source run.
- Reproducibility tests rerun CPU scenario generation and saved-snapshot loading from the manifest and require identical content hashes. MPS/CUDA checkpoints need not be bitwise identical across devices; portability and same-environment deterministic fixtures are tested separately.
- Failure-path tests cover partial SNB dates, duplicate rows, invalid units, unknown configuration keys, non-finite HJM paths, imbalanced snapshots, negative actions, missing artifacts, incompatible resume checkpoints, attempted final-test model selection, and omitted required seeds.
- Tests are separately invocable as fast unit/financial/gradient, bounded market-statistical, local end-to-end, device/portability, and optional extended-research groups. The default fast command starts no policy-training matrix; local end-to-end is explicit, and extended research and hardware-specific groups are never launched implicitly.
